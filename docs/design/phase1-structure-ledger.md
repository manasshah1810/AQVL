# Phase 1 Structure Ledger

Recorded 2026-09-29, before any Phase 2 work. It is analysis only: no engine, data structure, example, or doc was changed. Every claim below was checked against the current source; paths are relative to `packages/runtime/src/` unless stated. This ledger is Phase 2's scope list.

## Headline finding: the acid-test gap is partly stale

`docs/design/acid-test-report.md:15-17,142-145` says BST, Heap, Graph, HashMap and Trie are "opaque TypeScript runtime built-ins reached through a single keyword statement." `docs/design/algorithm-engine-pattern.md` describes the same five as the whole engine story. Neither matches the current source. **Every one of those five now has two independent runtime paths:**

1. **Opaque keyword path (legacy).** An `AlgorithmHandler` is registered in `AlgorithmRegistry` (`core/AnimationController.ts:16-49`) and reached by one keyword such as `HEAP_INSERT`, `TRIE_SEARCH` or `DIJKSTRA`. The algorithm runs in TypeScript.
2. **User-space AQVL path (newer).** A "program engine" is instantiated directly on `AnimationController` (`core/AnimationController.ts:87-103`) and is **not** registered in `AlgorithmRegistry`. It exposes only primitives, and the algorithm itself is written in AQVL: `h[i]`/`SWAP` for heaps, `m[key]`/`KEY_AT` for hash maps, `GET_CHILD`/`ADD_CHILD` for tries, `NEIGHBOR`/`v.field` for graphs, and `curr.left`/`NEW_NODE`/`FREE` for trees and lists.

**The shipped example corpus uses only path 2.** A grep of every `packages/demo/src/examples/*Library.ts` finds zero uses of `HEAP_*`, `HASHMAP_*`, `TRIE_*`, `BST_INSERT`, `BUBBLE_SORT`…`QUICK_SORT`, or `DIJKSTRA`/`BELLMAN_FORD`/`ASTAR`/`PRIM`/`KRUSKAL`/`TOPO_SORT`. The `DFS`/`BFS` hits in `GraphLibrary.ts` are all comments or `PRINT` strings (e.g. lines 195, 228, 320). The only one-line shortcuts used are `INSERT_TAIL`/`DELETE_HEAD` in the singly-linked-list example (`LinkedListLibrary.ts:56-57`). The README's claim that the examples are "real code" therefore holds for the corpus (see `phase1-example-corpus-audit.md`: 218/218 pass). The opaque path is still live, keyword-reachable surface that no example exercises.

## Pattern variant legend

The variants come from `algorithm-engine-pattern.md`:

- **Canonical** means a pure `data-structures/<Name>.ts` with `.steps` + a one-file `<Name>Engine implements AlgorithmHandler` that replays them (reference: Heap).
- **V1 step-array naming** means steps are recorded but under another name (`animationFrames`).
- **V2 pure/handler split** means the pure logic and the `AlgorithmHandler` live in two separate files.
- **V3 no step-recording** means the handler hand-writes the animation and no step array comes back from the pure layer.

Two further shapes are **not in the doc** and are added here:

- **V4 extracted-engine, no handler** means a plain class called directly by `AnimationController` (not `implements AlgorithmHandler`, not registered, no pure layer).
- **V5 scene-graph program engine** means the scene graph is the model, primitives are driven by the VM, and there are no step arrays and no pure layer.

## Coverage check against the README feature list

`README.md:95` lists these structures: arrays, linked lists (singly/doubly/circular), binary trees, BSTs, AVL trees, red-black trees, graphs, heaps, priority queues, hash maps, tries, union-find. Each has a row above. Stack and Queue appear in the README's examples (lines 165, 168, 170) and in the task's scope list, so they have rows too.

## Phase 2 scope implied (recorded, not acted on)

1. **Structures in the README that AQVL can't reach:** AVL tree and red-black tree (pure classes plus tests, but no keyword, engine, or export) are the largest README-vs-source gaps. Priority queue and union-find are internal helpers.
2. **Duplicated paths:** Heap, HashMap, Trie, Graph, BST and binary tree each have an opaque keyword handler alongside a primitive program engine. No example uses the opaque handlers, except that HashMap's and Trie's handlers still build declared structures.
3. **Stale design docs:** `acid-test-report.md` ("all opaque") and `algorithm-engine-pattern.md` (five structures, canonical = HeapEngine, `BSTEngine` = pure) both predate the program engines. The dominant shape in the codebase is now V5, which the pattern doc doesn't describe.
4. **Naming collisions and drift:** there are two `MinHeap` classes, `GraphAlgorithm` lives in `GraphEngine.ts`, `LinkedListEngine` is aliased to `LinkedListModel`, and stacks/queues each have two renderers.
